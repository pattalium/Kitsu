Manual/Firmware updates

SAFE WEB SERIAL INSTALL

Update Kitsu and keep the board yours.

Kitsu firmware is owner-reflashable. The official browser installer verifies the signed release, the board identity, the exact artifacts, the write addresses, and the bytes read back from flash.

Supported setup

  • Heltec WiFi LoRa 32 V3 or V3.2 with 8 MiB flash.
  • A desktop Chromium-based browser with Web Serial.
  • A known-good USB data cable.
  • No other serial terminal or flashing program using the same port.
  • Stable USB power for the entire operation.

Normal update

  1. Open the firmware installer.

    The page loads its flasher library locally; the device bytes do not pass through a third-party flashing service.

  2. Review the release shown.

    Install stays disabled unless the release manifest signature, hardware acceptance, artifact sizes, and SHA-256 values all verify.

  3. Connect the board and choose its serial port.

    The installer confirms ESP32-S3 and 8 MiB flash before any write.

  4. Start Install and leave the cable connected.

    The installer writes only the reviewed partition table and application regions.

  5. Wait for read-back verification and restart.

    The installer reads both written regions and compares their SHA-256 hashes with the signed manifest.

What the official update preserves

RegionNormal updateWhy
BootloaderPreservedThe supported board already has a compatible bootloader.
ApplicationUpdatedContains the Kitsu firmware.
Partition tableUpdated to the reviewed layoutDefines the application, companion pack, connectivity store, and recovery areas.
OTA statePreservedAvoids unrelated boot-state changes.
NVS and companion packPreservedKeeps device identity, companion state, and installed visual pack.
Connectivity storePreservedKeeps Wi-Fi and enrolled gateway material when compatible.
eFusesNever touchedKitsu does not permanently lock the board.
Never use Erase all for a routine update.A full-chip erase removes companion state, device identity data, packs, and connectivity. Use it only as an intentional recovery operation after making a complete backup and understanding what will be lost.

Recovery

If Kitsu does not boot after a verified update, disconnect power, make sure PRG is not held, reconnect, and wait for the normal boot. If the board remains in download mode or the display is blank, follow Troubleshooting before writing anything else.

Because the board remains owner-reflashable, you can install a previous verified Kitsu image or return to stock MeshCore. That flexibility also means physical access is not a tamper-proof security boundary.

Verify a download manually

The firmware installer performs the checks automatically. Advanced users can also download the signed update metadata and compare every declared byte length and SHA-256 value before using a serial tool. Do not invent addresses or add a bootloader write to the normal Kitsu release command.
