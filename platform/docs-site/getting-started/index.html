Manual/Getting started

FIRST-TIME SETUP

From a prepared Heltec board to your Kitsu.

You need a supported Heltec WiFi LoRa 32 V3 already prepared for the accepted 0.20.3 layout, an Android phone running Android 8 or newer, and about fifteen minutes. The one-time layout transition is a separate private service ceremony, not a public setup download.

1. Confirm current firmware

  1. Power on the prepared Kitsu normally.

    Do not hold PRG while resetting. The accepted public 0.20.3 journey begins after the private storage-layout transition has passed physical acceptance.

  2. Check the visible firmware identity.

    Use the Kitsu information screen to confirm firmware 0.20.3. The corresponding release record must identify the current 8 MiB dual-OTA layout with two 3 MiB application slots and private final-sector journals.

  3. Stop on 0.20.2 or an unknown layout.

    The one-time 0.20.2 to 0.20.3 transition preserves storage through two private full-flash backups, a fresh real-IDF NVS oracle, and a table-last migration. It is physically supervised and is not exposed as a public owner command or download.

  4. Use Android for later updates.

    After migration, download the exact signed .kitsu-fw from the Kitsu firmware card and install it over the existing authenticated Bluetooth connection.

Do not use the historical browser flasher.The immutable seven-write Web Serial release is authority only for its accepted pre-0.20.3 legacy layout. It writes legacy slots and the table too early, so it is blocked for migrated or unknown boards. Do not force it, use generic PlatformIO upload, or choose a full-chip erase.

2. Install Android

  1. Download an eligible local-first Android APK.

    Use the Android card on the Kitsu product page only when it shows a verified local-first release and enables the link, then allow installation from your browser when Android asks.

  2. Allow installation from your browser.

    Android may ask you to allow this source. That permission can be turned off again immediately after installation.

  3. Open Kitsu and grant nearby-device access.

    Android 12 and newer ask for Nearby devices. Android 8–11 may ask for Location because those versions tie Bluetooth scanning to that permission.

3. Put Kitsu in phone-pairing mode

  1. From Home, hold PRG for at least 750 ms.

    The main menu opens.

  2. Hold PRG while CONNECT is selected.

    The local connection menu opens with Bluetooth selected.

  3. Hold PRG on BLUETOOTH.

    Kitsu opens the time-limited PAIR PHONE window.

  4. In Android, open Settings and find Pair another Kitsu.

    Enter a phone label and tap Pair this phone.

4. Compare the code and grant the phone

  1. Compare Android's six digits with Kitsu's MATCH CODE screen.

    If they differ, cancel both sides and start again. Never approve a mismatch.

  2. Accept Android's pairing prompt.

    When Kitsu asks for confirmation and the codes match, hold PRG.

  3. Wait for the second physical prompt.

    The app shows that it is waiting for PRG; Kitsu shows PHONE READY.

  4. Hold PRG again to grant this phone.

    The device creates a controller credential for that installation of the app.

There are two PRG holds during phone setup.The first confirms the Bluetooth numeric comparison. The second grants the authenticated Kitsu controller. Both are intentional.

5. Confirm nearby control

  • The app should show Connected directly over authenticated Bluetooth and current companion status.
  • Try Pet or Feed and confirm Kitsu reacts.
  • Open Messages and inspect the device-reported history.
  • Tap Disconnect when finished. This closes Kitsu's connection but does not turn off the phone's Bluetooth radio.

6. Confirm offline operation

  1. Turn on airplane mode, then turn Bluetooth back on.

    This removes Wi-Fi and mobile data from the test while allowing the local radio.

  2. Select the saved Kitsu and tap Connect.

    The app must return to Connected directly over authenticated Bluetooth without a sign-in or service check.

  3. Try state, care, and messages.

    Read current needs, perform one care action, inspect peers or messages, then Disconnect and reconnect once.

  4. Open Settings.

    The saved-device list and signed .kitsu-fw picker are the complete connection and update controls. There is no gateway or Wi-Fi setup step.
