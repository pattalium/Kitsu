Manual/Android app

NATIVE ANDROID APP

Care, connect, message, disconnect.

Kitsu for Android pairs over authenticated Bluetooth and can carry up to three nearby Kitsu devices to the public gateway over the phone's Internet connection. The public gateway does not require an owner account or Heltec Wi-Fi.

Install and update

  • Android 8.0 or newer is required.
  • The current website APK is a signed Android release.
  • Download only from the signed link on the Kitsu product page.
  • The download page verifies a detached release signature before exposing the APK.
  • Install a newer release over the existing app to preserve its Android-keystore controller credential.
Current download.Install the signed Android APK from the Kitsu product page.

Connection modes

Direct Bluetooth
The phone is near the enrolled Heltec. Care, state, history, messages, Wi-Fi setup, and enrollment use the authenticated device session.
Public gateway
The phone stays near Kitsu and carries authenticated gateway traffic over its own Internet connection. No owner account or Heltec Wi-Fi is required.
Remote owner service
An optional signed-in owner can use fresh authenticated device snapshots and owner-scoped actions.
Disconnected
The user selected Disconnect. Scanning, GATT, notifications, direct transport, and remote fallback stay suppressed until the user selects Connect again—even after an app relaunch.

Connect and Disconnect

Connect starts the nearby-first connection flow. If a stored companion credential exists but the Android bond is missing, the app stops and asks for repair instead of silently falling back.

Use Wi-Fi remote access is an explicit owner choice. It closes the current Bluetooth transport and connects to the authenticated owner service without pretending the nearby device is absent.

Disconnect closes the Kitsu session and suppresses automatic reconnection. It does not turn off the phone's system-wide Bluetooth radio, disable the Heltec's MeshCore receiver, erase Wi-Fi, or cancel already accepted radio work.

Public gateway

  1. Pair Kitsu first.

    Use More → Pair this phone and complete both PRG confirmations.

  2. Tap Connect to public gateway.

    The button is available as soon as one Kitsu is paired; sign-in is not required.

  3. Hold PRG when Android asks.

    Kitsu shows the same GATEWAY enrollment prompt and countdown.

  4. Wait for Connected to public gateway.

    Android then maintains the Bluetooth-to-Internet bridge as a foreground service. Disconnect it from the same card.

Owner account: what it does and how to get it

An owner account is the private service identity that keeps remote companions and gateways attached to the right person. It is not a Bluetooth pairing code, a device administrator mode, proof of hardware ownership, or a requirement for nearby use.

No account needed

Bluetooth and public gateway

Pair the phone, use Kitsu nearby, and connect up to three paired devices through the phone to the public gateway. These paths use device- and installation-scoped credentials.

Owner account optional

Owner service and self-hosted gateways

Sign in only to load owner-scoped companions, use the separate owner service, or administer a self-hosted gateway.

Where the first username and password come from

There is no public registration button. During initial owner provisioning, the Kitsu service operator creates the account and produces a private bootstrap handoff containing the username and a temporary password. Until delivery over an authenticated private channel, the operator stores that handoff in a file readable only by the operator's service account; on Unix-like systems the file uses mode 0600. The public website and Android app cannot display, recreate, or guess it.

  1. Get the private handoff from the service operator.

    If someone else provisioned your Kitsu environment, ask that person for the initial owner credential handoff. Do not request or share it in a public issue.

  2. Tap Sign in under Owner account.

    Kitsu opens the system browser. The password is entered only on the sign-in page, never into the Android app itself.

  3. Enter the supplied username and temporary password.

    The first successful login requires you to replace the temporary password with a private permanent password.

  4. Return to Kitsu after the browser redirects.

    The app stores only encrypted session tokens in Android Keystore. You can then load trusted gateways and remote companions.

No handoff means remote access is not provisioned yet.Do not try unrelated passwords. Nearby Bluetooth continues to work without an account. Ask the service operator to provision the owner or issue a replacement handoff.

Recovery and support

There is no self-service email or public password reset. If the handoff or permanent password is lost, request the operator-run recovery procedure through the Kitsu support route. After manually confirming the request, the operator invalidates the old password, terminates its existing server-side sessions, and issues a new temporary password in a new one-time private handoff. Never include a password, bootstrap handoff, private key, Wi-Fi passphrase, or access token in the form, screenshots, or diagnostic logs.

Sign out

Sign out clears the app's remote session and revokes tokens where supported. It does not unpair Bluetooth, erase the local controller credential, remove Wi-Fi, or reconnect an explicitly disconnected session. Direct Bluetooth remains available without signing in.

Cancel during setup

Before the physical enrollment confirmation, Stop setup disconnects Bluetooth so the Heltec wipes the staged claim. After Kitsu has accepted the PRG enrollment hold and reports that the handoff is committed, the app no longer claims it can cancel the device-side operation; it can only stop waiting for the result.

The app never needs Bluetooth forever.After remote enrollment, a signed-in owner can select Wi-Fi remote access to close the nearby transport and use the authenticated gateway path. Use Disconnect when you want both app transports to stop. Kitsu can continue locally, receive MeshCore traffic, and keep its configured Wi-Fi association independently.
