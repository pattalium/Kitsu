Manual/Android app

LOCAL-FIRST ANDROID APP

Care, message, update, and disconnect nearby.

Kitsu for Android uses authenticated Bluetooth only. It has no sign-in screen, account, gateway control, Wi-Fi setup, background relay, or Internet permission. Every device control corresponds to a real nearby operation.

Install and update Android

  • Android 8.0 or newer is required.
  • Install the signed APK from the verified link on the Kitsu product page.
  • The download page verifies a detached release signature before exposing the APK.
  • Install a newer release over the existing app so Android preserves the Keystore-backed controller records.
  • The same production signing certificate lets Android verify that an update belongs to Kitsu.

Saved Kitsu and updates

Select, connect, disconnect, pair another device, forget authorization, and install signed firmware.

Saved Kitsu controls

The app stores up to three Kitsu authorizations. Select chooses which saved device appears in the rest of the app. Connect opens its authenticated Bluetooth session. Disconnect closes that session without deleting authorization. These are per-device controls; changing one saved Kitsu does not invent a global server state.

Pair another Kitsu

  1. Open CONNECT, then BLUETOOTH, on the Heltec.

    Hold each selected item to start the bounded PAIR PHONE window.

  2. In Android Settings, enter a phone label and tap Pair this phone.

    The app scans only after the required Android permission is available.

  3. Compare the six digits.

    Accept Android's system pairing prompt and hold PRG only when the number on the phone exactly matches the number on Kitsu.

  4. Grant the controller.

    When Kitsu shows PHONE READY, hold PRG again. The new Kitsu becomes saved and selected.

Forget authorization

Forget is not a cosmetic delete. The selected Kitsu must be nearby; the app connects to it if needed and sends the authenticated controller.forget request. Kitsu durably revokes this phone's controller root, returns an accepted receipt, drains the response, and closes the connection. Android then deletes the matching local credential. If that final receipt is lost, the persisted Finish forgetting state verifies the revocation by the rejected old credential before deleting it locally. Packs, companion progression, MeshCore state, and other authorized phones stay intact.

Offline firmware update

  1. Download a signed .kitsu-fw package in your browser.

    The browser is only the download tool. The Kitsu app itself does not fetch from the Internet.

  2. In Settings, tap Choose .kitsu-fw.

    Android verifies the exact container, canonical manifest, Kitsu Ed25519 signature, ESP32-S3 image structure, image size, and SHA-256 before enabling Install.

  3. Connect the selected Kitsu and tap Install.

    Keep the device powered, nearby, and the app visible. Transfer resumes from the device's authoritative checkpoint after a recoverable disconnect.

  4. Let Kitsu reboot and confirm itself.

    The inactive A/B slot boots first. If the new image cannot remain healthy, the ESP bootloader returns to the previous slot. The app reports confirmed or rolled back instead of claiming success early.
