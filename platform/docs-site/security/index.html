Manual/Security and privacy

SECURITY MODEL

Strong network identity. Reflashable hardware.

Kitsu protects normal Bluetooth, Wi-Fi, and Internet use without permanently locking the Heltec. That is a deliberate tradeoff: the owner keeps full recovery and repurposing rights, while physical possession of the board remains a powerful trust boundary.

What is protected

  • Bluetooth setup uses LE Secure Connections, numeric comparison, physical PRG approval, a device-issued controller credential, per-session keys, authenticated frames, sequence numbers, and replay protection.
  • Wi-Fi credentials and gateway trust are accepted only inside the authenticated Bluetooth session.
  • Remote device connections use pinned TLS and mutual certificate authentication.
  • Remote actions carry owner authorization, an expiry, an idempotency identifier, a backend signature, and device-side replay checks.
  • The Android app keeps the controller root in Android Keystore and encrypts its local cache.
  • Release downloads use signed manifests and exact SHA-256 checks.

What owner-reflashable means

Kitsu does not burn permanent eFuses, enable irreversible Secure Boot, encrypt the whole flash with a hardware-only key, disable JTAG, or lock serial download mode. You can erase the board, install another verified Kitsu release, restore stock MeshCore, or reuse the hardware.

Physical access can bypass application controls.Someone holding the board can read unencrypted flash or replace the firmware. Kitsu does not claim tamper resistance, verified boot, or protection against a determined physical attacker.

Data on the device

Companion state, installed pack data, controller enrollment, message journals, Wi-Fi configuration, and gateway credentials are stored in dedicated flash areas. The application encrypts sensitive connectivity generations, authenticates them, verifies read-back, and keeps an older valid generation for power-loss recovery. Because the hardware is reflashable and full-flash encryption is not enabled, this is application protection rather than a physical-security guarantee.

Data in Android

  • Controller credentials stay in Android Keystore-backed encrypted storage.
  • Cached companion data is encrypted and excluded from Android backups.
  • Wi-Fi passphrases are transient inputs: they are not saved in app preferences, logs, or release artifacts.
  • Disconnect suppression is a non-secret preference so an explicit Disconnect survives process death and relaunch.

Data used by remote access

Remote access stores the minimum records needed to bind an owner, companion, and gateway; deliver current state and messages; reject replay; process queued actions; maintain certificates; rate-limit abuse; and audit security-relevant events. Retention and deletion details are in the public privacy policy.

Terms you may see

OIDC
OpenID Connect, the browser-based sign-in protocol used by the Android and web apps.
PKCE
A proof used during native sign-in so an intercepted authorization code cannot be redeemed by another app.
Private CA (PCA)
The private certificate authority that issues and verifies device and gateway identities for authenticated network connections. It is internal to Kitsu's remote service and is not a public website certificate authority.
SPKI pin
A SHA-256 fingerprint of the expected server public key, provisioned to the device over authenticated Bluetooth.
mTLS
Mutual TLS: both sides present and verify certificates instead of authenticating only the server.
KMS
A protected key provider used by backend services so raw master keys are not stored in ordinary application data.
Envoy
The backend service-edge proxy that handles protected service connections, routes authenticated traffic, and enforces network policy. It is not an account, an Android setting, or something a normal Kitsu user configures.
Replay protection
Sequence numbers, expiries, and durable action identifiers that stop a valid old request from being accepted again.

Good owner practices

  • Approve pairing only when both six-digit values match.
  • Press PRG only when you initiated the action and the screen describes what is being approved.
  • Install Android and firmware only from signed Kitsu release links.
  • Do not send secrets through MeshCore messages.
  • Keep private flash backups encrypted and off public storage.
  • Use Disconnect when you want the phone app to remain idle.
