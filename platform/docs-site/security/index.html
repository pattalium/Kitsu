Manual/Security and privacy

LOCAL SECURITY MODEL

Authenticated Bluetooth. Signed updates. Reflashable hardware.

Kitsu removes the account and runtime-service trust boundary. The phone proves a physically approved controller credential directly to the nearby Heltec. The owner keeps full recovery and repurposing rights, so physical possession of the board remains powerful.

What is protected

  • Bluetooth setup uses LE Secure Connections, numeric comparison, physical PRG approval, a device-issued controller credential, per-session keys, authenticated frames, sequence numbers, and replay protection.
  • The Android app keeps controller roots in Android Keystore-backed encrypted storage and encrypts its bounded local cache.
  • The Android application has no Internet permission, account token, runtime-service client, or background relay.
  • Forget authorization durably revokes the selected controller on the Heltec before Android removes its local copy.
  • Firmware packages use an offline Ed25519 authority, canonical signed manifest, exact SHA-256, strict ESP32-S3 image validation, inactive-slot writes, readback, and bootloader rollback.
  • Public Android downloads use signed manifests, exact SHA-256, and the stable Android application certificate.

What owner-reflashable means

Kitsu does not burn permanent eFuses, enable irreversible Secure Boot, encrypt the whole flash with a hardware-only key, disable JTAG, or lock serial download mode. You can erase the board, install another verified Kitsu release, restore stock MeshCore, or reuse the hardware.

Physical access can bypass application controls.Someone holding the board can read unencrypted flash or replace the firmware. Kitsu does not claim tamper resistance, verified boot, or protection against a determined physical attacker.

Data on the device

Companion state, installed pack data, controller authorization, message journals, MeshCore configuration, and OTA recovery metadata are stored in dedicated flash areas. Controller roots use authenticated generations and read-back verification. Because the hardware is reflashable and full-flash encryption is not enabled, this is application protection rather than a physical-security guarantee. The local-only bootstrap and firmware erase and verify the isolated region that held legacy Wi-Fi and gateway secrets, and remove only the retired LAN-action namespace; companion, controller, and MeshCore records are preserved.

Data in Android

  • Controller credentials stay in Android Keystore-backed encrypted storage.
  • Cached companion data is encrypted and excluded from Android backups.
  • Saved-device selection and disconnect state are local preferences.
  • Imported firmware is accepted only after offline signature, schema, target, image-layout, size, and hash verification.
  • No companion state, pairing data, or diagnostics are uploaded by the app.

Terms you may see

Controller root
The device-issued secret that represents one physically approved installation of the Android app. It is not an account password.
Application handshake
The authenticated exchange after Android's bonded GATT connection that derives fresh session keys and proves the saved controller.
Replay protection
Sequence numbers and durable action identifiers that stop a valid old Bluetooth request from being accepted again.
Ed25519 update authority
The offline signing key whose public half is embedded in the app, firmware, and release tooling. It authorizes a canonical firmware manifest, not arbitrary flash commands.
A/B update
Writing the non-running application slot and trying it once while the previous slot remains available for rollback.
Pending verify
The first boot state of a new image. Kitsu confirms it only after critical local initialization and 30 seconds of healthy execution.

Good owner practices

  • Approve pairing only when both six-digit values match.
  • Press PRG only when you initiated the action and the screen describes what is being approved.
  • Install Android and firmware only from signed Kitsu release links.
  • Keep Kitsu powered, nearby, and the app visible during Bluetooth OTA.
  • Do not send secrets through MeshCore messages.
  • Keep private flash backups encrypted and off public storage.
  • Use Disconnect for a temporary stop and Forget authorization only when you intend to revoke this phone.
