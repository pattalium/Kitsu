Manual/Troubleshooting

DIAGNOSE BEFORE RESETTING

Fix the path that is actually failing.

Kitsu deliberately keeps Bluetooth, Wi-Fi, remote access, and MeshCore as separate paths. Check the relevant state before erasing data or reflashing.

The display is off

  • Short-press PRG once. The OLED may simply be power-saving.
  • Confirm the board has stable power.
  • Do not hold PRG while reconnecting power; that can enter firmware-download mode.
  • If the display remains blank, connect USB and use the official installer to identify the board before writing.

Android cannot find Kitsu

  1. Open PHONE on the device.

    The pairing window is time-limited and must be visible.

  2. Check Android permissions.

    Grant Nearby devices on Android 12+, or Location permission and enabled Location services on Android 8–11.

  3. Move the phone close to the Heltec.

    Temporarily separate it from other active Kitsu boards.

  4. Try Connect again.

    A scanner error is not treated as proof that the companion is absent; the app should show the specific failure.

The pairing code does not match

Cancel immediately on both devices. Do not press PRG to accept it. Close PHONE, reopen it, start setup again, and compare the new six-digit value carefully.

Android says the bond is missing

The app has a Kitsu controller credential but Android no longer has the matching Bluetooth bond. Use the app's repair/setup flow, remove only the stale Android Bluetooth entry if instructed, then repeat the numeric comparison and both PRG confirmations.

Wi-Fi does not connect

  • Confirm the network provides 2.4 GHz service.
  • Re-enter the exact network name and passphrase over Direct Bluetooth.
  • Choose WPA2, WPA2/WPA3, or WPA3 to match the network.
  • Read the two app states separately: credentials stored proves the encrypted record was written and read back; Wi-Fi connected proves the radio has joined the access point.
  • You may keep Direct Bluetooth open while checking association. Firmware 0.10.2 keeps the Wi-Fi station warm during nearby setup, and the Connect screen can force an immediate Wi-Fi retry.
  • If the state remains Connecting or Backoff, check the network name, security mode, passphrase, and signal, then use Retry Wi-Fi or submit a replacement configuration once.

Remote mode stays unavailable

  • Confirm Wi-Fi is configured and the device shows an associated state.
  • Confirm a gateway was selected and physical enrollment completed.
  • Wait for trusted time; TLS will not start with an invalid clock.
  • Verify the Android app is signed in.
  • The normal Connect flow prefers Direct Bluetooth when the known companion is nearby. Use Wi-Fi remote access is the explicit owner-selected override.
  • Remote mode requires a fresh, device-authenticated snapshot. A stale database record is not enough.

A message is rejected

  • Refresh peers and channels.
  • Use a full direct recipient identity, not a shortened display ID.
  • Keep text at or below 128 UTF-8 bytes.
  • Confirm the selected channel slot is configured.
  • Confirm MeshCore and transmit policy are enabled.
  • Wait for radio duty-cycle availability before sending again.

Disconnect did not turn off Bluetooth

This is expected. Kitsu's Disconnect closes scanning, GATT, notifications, direct transport, and remote fallback for the app. Android does not allow one application to switch off the phone's global Bluetooth radio on behalf of every other application.

The firmware installer cannot open the port

  • Close serial monitors, terminal programs, and other browser tabs using the board.
  • Reconnect the USB cable and reopen the installer.
  • Use a data-capable cable and a direct USB port.
  • On Windows, confirm the USB-to-serial driver exposes a COM port.
  • If the board is in download mode, release PRG and restart before retrying a normal update.

Before a destructive recovery

Stop before full-chip erase.A verified normal update does not require it. Full erase removes companion state, installed pack data, device records, and connectivity. Make a complete flash backup first and keep it somewhere private.

Still stuck?

Collect the app version, firmware version, Android version, the exact screen or connection state, and the last action taken. Do not include passwords, private keys, Wi-Fi credentials, or other people's radio traffic. Send the report through the Kitsu contact form.
