Manual/Troubleshooting

DIAGNOSE BEFORE RESETTING

Fix the local path that is actually failing.

The supported control path is authenticated Bluetooth. MeshCore radio and firmware recovery are separate local paths. There is no account, gateway, Wi-Fi, or remote fallback to debug.

The display is off

  • Short-press PRG once. The OLED may simply be power-saving.
  • Confirm the board has stable power.
  • Do not hold PRG while reconnecting power; that can enter firmware-download mode.
  • If the display remains blank, connect USB and use the official installer to identify the board before writing.

Pair this phone cannot find Kitsu

  1. Open CONNECT, then BLUETOOTH, on the device.

    Hold each selected item. The time-limited PAIR PHONE window must be visible.

  2. Check Android permissions.

    Grant Nearby devices on Android 12+, or Location permission and enabled Location services on Android 8–11.

  3. Move the phone close to the Heltec.

    Temporarily separate it from other active Kitsu boards.

  4. Tap Pair this phone again.

    A scanner error is not treated as proof that the companion is absent; the app shows the specific failure.

The pairing code does not match

Cancel immediately on both devices. Do not press PRG to accept it. Close PAIR PHONE, reopen it through CONNECT → BLUETOOTH, start setup again, and compare the new six-digit value carefully.

Android says the bond is missing

The app has a Kitsu controller credential but Android no longer has the matching Bluetooth bond. Reopen PAIR PHONE through CONNECT → BLUETOOTH, then use Settings → Pair another Kitsu → Pair this phone and repeat the numeric comparison and both PRG confirmations.

Connect fails after it worked before

  • Confirm the correct saved Kitsu is selected and nearby.
  • Turn Bluetooth on; airplane mode is fine after Bluetooth is turned back on.
  • Wake the Heltec display with a short PRG press and keep the phone close.
  • If Android reports a missing bond or handshake rejection, repeat pairing for that Kitsu. The app does not hide the failure by switching transports.
  • If another phone is currently connected, disconnect it before retrying.

A message is rejected

  • Reconnect Kitsu so the app reloads peers and channels.
  • Use a full direct recipient identity, not a shortened display ID.
  • Keep text at or below 128 UTF-8 bytes.
  • Confirm the selected channel slot is configured.
  • Turn on Local mesh radio in the Mesh tab.
  • Wait for radio duty-cycle availability before sending again.

Disconnect did not turn off Bluetooth

This is expected. Kitsu's Disconnect closes its scan, GATT session, notifications, and authenticated transport. Android does not allow one application to switch off the phone's global Bluetooth radio on behalf of every other application.

A Bluetooth firmware update stops

  • Keep Kitsu powered, keep the app visible, and move the phone close to the device.
  • Reconnect the same saved Kitsu and choose the exact same signed package. The device reports its durable offset and the app resumes.
  • If the app shows a terminal failed state, use Reset interrupted update, verify Idle, then start again.
  • If Kitsu rebooted but did not confirm, wait for the previous slot to return. The app should report Rolled back rather than Connected or Updated.
  • Do not import a renamed raw .bin; Android accepts only the exact signed .kitsu-fw container.

The firmware installer cannot open the port

  • Close serial monitors, terminal programs, and other browser tabs using the board.
  • Reconnect the USB cable and reopen the installer.
  • Use a data-capable cable and a direct USB port.
  • On Windows, confirm the USB-to-serial driver exposes a COM port.
  • If the board is in download mode, release PRG and restart before retrying a normal update.

Before a destructive recovery

Stop before full-chip erase.A verified Bluetooth update or Web Serial recovery does not require it. Full erase removes companion state, installed pack data, controller authorizations, MeshCore configuration, and recovery records. Make a complete flash backup first and keep it somewhere private.

Still stuck?

Collect the app version, firmware version, Android version, selected device name, the exact displayed error, and the last action taken. Do not include controller credentials, private keys, full flash dumps, or other people's radio traffic. Use the links on the Kitsu support page.
