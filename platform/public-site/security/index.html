SECURITY CONTACT - UPDATED 22 AUGUST 2026

Report a security issue

How to report

Use the repository's private vulnerability reporting. Include the affected release or component, impact, reproducible steps, and a safe reply route. Do not include controller credentials, private keys, complete flash dumps, or personal radio traffic in a public issue.

Safe research

Good-faith testing must use systems and devices you own or have explicit permission to test. Avoid privacy impact, denial of service, social engineering, persistence, destructive actions, and access to other people's information. Stop and report if sensitive data is encountered.

Response

Private reports are reviewed through the source repository. There is no promise of a bounty or fixed response deadline. Confirmed issues are prioritized by exploitability and impact; public disclosure should wait until a fix or mutually agreed date.

Security boundary

The supported product boundary is the signed Android application, authenticated Bluetooth protocol, signed A/B firmware updater, MeshCore integration, and public release surfaces. Physical possession of this deliberately reflashable board remains a powerful trust boundary and is not treated as tamper resistance.
